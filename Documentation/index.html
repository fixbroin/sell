⚡ Quick Start Guide (5-Minute Fast Track)

Follow these 4 simple steps to run the complete WeCanFix customer app, provider portal, and admin dashboard on your machine in under 5 minutes:

Step 1: Extract Files & Set Environment Variables

Unzip your purchased source package, navigate into the project directory, and create your .env configuration from the example template:

cp .env.example .env

Open .env and fill in your MySQL database credentials (e.g. DATABASE_URL="mysql://root:password@localhost:3306/wecanfix").

Step 2: Install Dependencies

Install all required project dependencies (Node.js 18+ or 20+ LTS recommended):

npm install

Step 3: Initialize Database & Seed Defaults

Run the automated database migration script. This automatically creates all required MySQL tables, default settings, service categories, and initializes the super administrator account:

npm run db:init

Step 4: Launch the Application

Start the local Next.js development server:

npm run dev
🎉 Application Ready!
  • Customer Web App: http://localhost:3006
  • Provider Panel: http://localhost:3006/provider
  • Super Admin Dashboard: http://localhost:3006/admin

1. Overview & Architecture

WeCanFix is built on the latest Next.js 15 App Router architecture. It separates presentation, business logic, and database persistence into clean, maintainable layers:

  • Frontend Layer: Next.js Server & Client Components styled with Tailwind CSS and Radix UI primitives.
  • API Handler Layer: Secure Server Route Handlers located under src/app/api/ with input validation using Zod.
  • Database Layer: MySQL 5.7+ / 8.0+ connected via connection-pooled mysql2 with automated schema migration.
  • Authentication Layer: Firebase Authentication for Phone OTP, Google OAuth, and Email login.

5. MySQL Database Setup

You can create your MySQL database on any VPS or shared hosting cPanel server using the following SQL commands:

CREATE DATABASE wecanfix CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'wecanfix_user'@'localhost' IDENTIFIED BY 'StrongPassword123!';
GRANT ALL PRIVILEGES ON wecanfix.* TO 'wecanfix_user'@'localhost';
FLUSH PRIVILEGES;

Then run the automated database initialization script:

npm run db:init

6. Firebase Integration Guide

Firebase handles customer and provider phone OTP authentication, Google sign-in, and Web Push notifications.

Step 1: Create a Project in Firebase Console

Navigate to the Firebase Console and click Add project.

Step 2: Enable Authentication Methods

Go to Authentication → Sign-in method and enable Phone, Google, and Email/Password.

Step 3: Generate Admin SDK Service Account

Go to Project Settings → Service Accounts, select Node.js, and click Generate new private key. Copy the project_id, client_email, and private_key into your .env file.

8. VPS & PM2 Setup (Ubuntu/Debian Production Guide)

Recommended production deployment using Nginx reverse proxy and PM2 process manager:

Install Node.js, Nginx & PM2

curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs nginx git
sudo npm install -g pm2

Build and Start with PM2

npm install
npm run build
pm2 start npm --name "wecanfix" -- start
pm2 save
pm2 startup

Configure Nginx Reverse Proxy

Create /etc/nginx/sites-available/wecanfix:

server {
    server_name yourdomain.com www.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:3006;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}

Enable the site and issue SSL:

sudo ln -s /etc/nginx/sites-available/wecanfix /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com

9. Local Standalone Build (For Low-RAM VPS)

If your VPS has limited RAM (1GB or less), you can build the Next.js standalone package on your local computer and upload only the lightweight build artifacts:

  1. Run npm run build locally on your machine.
  2. Next.js will generate a self-contained bundle in .next/standalone.
  3. Copy public/ and .next/static/ into .next/standalone/.
  4. Upload the lightweight standalone folder to your VPS and start via node server.js.

  3. Update DATABASE_URL in your VPS .env with the shared hosting domain/IP.

🛠️ Comprehensive Troubleshooting Guide (Common Installation Errors)

Solutions for the most common installation, build, database, and third-party configuration scenarios:

ECONNREFUSED 1. Database Connection Refused / ER_ACCESS_DENIED_ERROR
▼

Cause: MySQL server is stopped, user credentials in .env are incorrect, or MySQL is not accepting connections on port 3306.

Fix:

  1. Verify MySQL is running: sudo systemctl status mysql (start with sudo systemctl start mysql).
  2. Test connection in terminal: mysql -u wecanfix_user -p -h 127.0.0.1 wecanfix.
  3. Ensure DATABASE_URL in .env matches: mysql://wecanfix_user:password@127.0.0.1:3306/wecanfix.
BUILD ERROR 2. JavaScript Heap Out of Memory during 'npm run build'
▼

Cause: Node.js memory limit (default 1.5GB) reached during webpack compilation on lower-RAM servers.

Fix: Increase the Node memory allocation flag before running build:

export NODE_OPTIONS="--max-old-space-size=4096"
npm run build
NGINX 502 3. Nginx 502 Bad Gateway / Application Not Reachable
▼

Cause: Node process is not running or listening on a different port than configured in Nginx.

Fix:

  1. Check PM2 status: pm2 status and logs: pm2 logs wecanfix.
  2. Verify application port in package.json (default 3006).
  3. Ensure proxy_pass http://127.0.0.1:3006; in Nginx configuration matches the port.
FIREBASE KEY 4. Firebase Admin SDK "Failed to parse private key"
▼

Cause: Line breaks in RSA Private Key are escaped as literal \n strings inside .env.

Fix: Enclose the private key in double quotes in your .env file:

FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\nMIIEvgIBADANBgkqhkiG9w0BAQEFAASCBKgwggSkAgEAAoIBAQC...\n-----END PRIVATE KEY-----\n"
GOOGLE MAPS 5. "This page can't load Google Maps correctly" / ApiNotActivatedMapError
▼

Cause: Maps JavaScript API or Places API is not enabled in Google Cloud Console, or billing is not linked.

Fix:

  1. Open Google Cloud API Library.
  2. Enable: Maps JavaScript API, Places API, and Geocoding API.
  3. Ensure a valid Cloud Billing account is attached to your Google Cloud project.
WEBHOOK 400 6. Stripe or Razorpay Webhook Signature Verification Failed
▼

Cause: Webhook secret in admin settings does not match the signing secret generated by Stripe/Razorpay.

Fix:

  1. Copy the exact Webhook Signing Secret (starts with whsec_... on Stripe).
  2. Paste it under Admin Panel → Platform Settings → Payments → Stripe Webhook Secret.
  3. Ensure your domain has valid HTTPS SSL (webhooks fail over plain HTTP).
413 PAYLOAD 7. 413 Request Entity Too Large on Image / Document Uploads
▼

Cause: Nginx default upload limit is 1MB.

Fix: Add client_max_body_size 64M; inside your Nginx server block:

server {
    ...
    client_max_body_size 64M;
    ...
}

Then reload Nginx: sudo systemctl reload nginx.

PWA SSL 8. Push Notifications / Service Worker Not Registering
▼

Cause: Service Workers and Web Push notifications require a secure origin (https:// or localhost).

Fix: Install an SSL certificate on your production domain using Certbot (sudo certbot --nginx). Service workers will automatically register upon first visit.
